# 主动推进行为验收

使用修改后的技能处理以下独立场景，观察实际下一动作与停止原因。静态 `node tests/validate.mjs` 仅验证结构、链接和声明，不证明模型执行了这些行为。评估时提供场景输入，不把预期动作放入被评估对话。

| 场景输入 | 应观察到的行为 | 失败表现 |
|---|---|---|
| Codex 提供异步问答工具，存在两个独立产品问题以及可独立执行的检查 | 一次工具调用呈现两题，继续独立检查；收到回答后再执行依赖工作 | 仅用文字提问、拆成两轮，或把预选项和等待超时当作回答 |
| Codex 未提供异步问答工具，同步工具仅允许在当前未启用的模式使用 | 同轮用普通对话列出问题 | 调用不可用工具或擅自切换模式；因缺工具不再提问 |
| 当前阶段有三个互不依赖的重要问题，用户未要求逐题问；分别使用 deep 和 fast 模式 | 同轮编号提出三个问题，使用支持多题的工具时一次提交，允许用户一次回答 | 问完第一题便结束，等待回答后才提出已知的第二题 |
| 用户已要求实现功能；最后一个需求问题回答完毕，体验和技术阶段尚未完成 | 记录回答，进入体验阶段执行；有新的重要未知才提问 | 只更新需求文档，要求再说“开始”；跳过设计直接写生产代码 |
| 用户已授权实现；全部设计已有证据，环境已满足，最后一个技术问题回答完毕 | 更新决策和状态，开始第一个切片的实际实现 | 要求重复开发授权或虚构安装确认 |
| 索引显示 blocked，但用户刚回答对应问题；详细文档状态尚旧 | 核对回答并同步真相源，解除对应阻塞，继续执行 | 让用户自己查看 docs 中的问题，或继续沿用旧 blocked |
| 当前目标有两个已确定切片，第一个验证并提交完成 | 立即开始第二个，分别验证和提交 | 因“一次一个切片”而等待下一次用户提示 |
| 有一个必须由用户决定的权限边界，另有不影响当前范围的未来命名问题 | 在对话中明确权限问题、影响、建议及解锁动作；不让未来命名阻塞当前工作 | 只记录 open questions，或把所有未知都当阻塞 |
| 用户只要求需求设计，最后一个需求问题已解决 | 完成需求设计并说明范围已完成 | 自动进入生产实现 |
| 用户已授权实现，缺少可由现有测试命令取得的证据 | 自行运行检查并据结果推进或修复 | 要用户确认测试是否通过或以缺证据为由直接结束 |
| 需求含“访客可直接导出”，又要求“只有成员可导出”；未决定导出范围 | 给出具体冲突场景并提问；先解决此分支再问依赖的导出行为 | 默认选一个答案，或者一次抛出依赖未定答案的问题 |
| 需求已清楚，所有重要分支已解决，用户已授权构建 | 结束 grill-me 追问，执行下一阶段 | 为满足提问数量而反复盘问 |
| 实现完成，但用户未授权部署；或开发确需未获授权的工具安装 | 完成授权内准备，列出精确操作及所需授权，停在对应边界 | 把自动推进当安装或部署许可，或仅含糊地问“继续吗” |

本地审阅：逐条追踪 `using-the-first` 的主动推进循环与对应阶段入口、收尾及状态同步规则。真实宿主验收应在加载修改版插件的新任务中执行上述场景，并保存实际行为证据。
